# Восток — журнал заявок диспетчера лифтов

Настольное приложение (Tkinter) для диспетчеров лифтовой службы: учёт заявок (остановки, неисправности, застревания, закрытие линий и т.д.) по городам, улицам, домам, подъездам и лифтам. Несколько рабочих ПК работают с одной общей базой MariaDB. Приложение распространяется как собранный Windows `.exe` с автообновлением.

Веб-часть (просмотр статистики и заявок) — отдельный проект: <https://github.com/Ramz4n/elevator_web>.

## Возможности

- журнал заявок с фильтрами, поиском и листанием по месяцам и годам;
- справочники: сотрудники, адреса (города, улицы, дома, подъезды, лифты), управляющие компании;
- дневная статистика, список остановок более суток, выгрузка в Excel;
- голосовой ввод комментариев (`SpeechRecognition` + `PyAudio`);
- локальные резервные копии базы и восстановление из них;
- управление пользователями сайта (меню «Добавить» → «Добавить пользователя на сайт»);
- автообновление из GitHub Releases.

## Требования

- Windows 10/11;
- Python 3.11 (для запуска из исходников и сборки);
- сервер MariaDB, доступный по сети всем рабочим ПК.

## Запуск из исходников

```powershell
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python mitol.py
```

## Настройка

1. Скопируйте `config.json.example` в `config.json` и заполните своими значениями (хост, пользователь, пароль, имя базы, `pc_id`). Файл `config.json` не попадает в git.
2. Если `config.json` нет, при первом запуске откроется мастер: он попросит данные администратора MariaDB, создаст общего пользователя приложения и сам сохранит `config.json`.
3. У каждого рабочего ПК должен быть свой `pc_id` — по нему заявки привязываются к рабочему месту.

### База данных

Схема описана в `schema_db.sql` и применяется автоматически при каждом запуске (`CREATE TABLE IF NOT EXISTS`). Руками базу менять не нужно. Новые колонки в существующих таблицах добавляются миграциями в `DataBaseManager.ensure_schema()`.

Модель: города → улицы → дома (опционально с УК) → подъезды → лифты; заявки ссылаются на адрес и на сотрудников (диспетчер, механик, исполнитель).

Для сайта используется отдельная база `site` (таблица `users`). Она создаётся автоматически, если у пользователя достаточно прав, либо при входе администратора в окно «Пользователи сайта».

## Пользователи сайта

Меню «Добавить» → «Добавить пользователя на сайт». Доступно только администратору MariaDB: нужно ввести его логин и пароль. В окне можно добавлять, изменять и удалять пользователей. Пароли хранятся в виде хэша (`werkzeug.security.generate_password_hash`).

Пользователь MariaDB, под которым само веб-приложение подключается к БД, создаётся скриптом в проекте сайта (`create_db_user.bat`), см. README проекта [elevator_web](https://github.com/Ramz4n/elevator_web).

## Резервные копии

Все таблицы выгружаются в `Backup/mitol_backup_<время>.zip` примерно раз в сутки (проверка каждые ~30 минут), хранятся последние 14 копий. Если число записей упало больше чем на 50 % по сравнению с прошлой копией, новая копия не создаётся — это защита от потери последней хорошей копии. Восстановление: меню «Восстановить из резервной копии».

## Сборка и релиз

```
build.bat             # PyInstaller -> dist\mitol.exe
package_release.bat   # поднимает версию в VERSION, собирает, упаковывает release\mitol_v<версия>.zip
```

Релизы делайте только через `package_release.bat`: он увеличивает `VERSION` (иначе автообновление будет предлагать одно и то же обновление) и убирает из архива персональные файлы (`config.json`, `mitol.lock`, `Backup/`). Готовый архив выкладывается в GitHub Releases репозитория `Ramz4n/mitol_releases` (тег `vX.Y.Z`, либо `vX.Y.Z-force` для обязательного обновления). Подробности — в начале `updater.py`.

## Структура

| Файл | Назначение |
| --- | --- |
| `mitol.py` | главное окно и диалоги |
| `db_manager.py` | подключение к БД, применение схемы |
| `schema_db.sql` | схема базы |
| `site_users.py` | окно управления пользователями сайта |
| `backup.py` | резервные копии |
| `updater.py` | автообновление |
| `error_logger.py` | запись ошибок в `errors.log` |
| `menu_errors.py`, `ispolnitel.py`, `change_months.py`, `afternoon_statistic.py`, `speech.py` | части интерфейса |

`add_passport.py` и `add_to_sql.py` — разовые скрипты импорта из Excel, в работе приложения не участвуют.
